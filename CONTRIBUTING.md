# Contributing

Tinlance is developed with a production-first engineering standard.

## Development principles

- Keep changes small and reviewable.
- Preserve strict TypeScript settings.
- Add tests for behavior that can regress.
- Never commit credentials, client data, or production secrets.
- Prefer secure-by-default APIs and explicit authorization checks.
- Update architecture documentation when a material design decision changes.

## Pull requests

Every PR should explain the problem, the change, validation performed, and any security or operational considerations.
