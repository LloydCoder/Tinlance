# Tinlance Visual System — V1

## Direction

Tinlance is positioned as a premium AI engineering and Forward Deployed Engineering partner. The visual system deliberately avoids generic AI imagery, excessive gradients, and agency-template patterns.

### Design principles

1. **Engineering first** — interfaces should feel precise, technical, and operational.
2. **Outcome over novelty** — visual hierarchy leads users from problem to capability to proof to action.
3. **Evidence over decoration** — systems, architecture, security, shipped work, and measurable outcomes carry the visual narrative.
4. **Quiet confidence** — restrained motion, strong typography, generous whitespace, and high information quality.
5. **Enterprise-ready** — accessible contrast, responsive behavior, reduced-motion support, semantic HTML, and fast-loading primitives.

## Visual language

- Base: warm off-white / graphite rather than pure white.
- Accent: acid green used sparingly for action and system-state emphasis.
- Dark sections: near-black engineering surfaces for contrast and depth.
- Typography: large editorial headlines paired with compact monospace technical labels.
- Surfaces: thin borders, restrained radii, minimal shadows.
- Graphics: system maps, data-flow motifs, technical diagrams, and real product evidence rather than stock photography.

## Homepage hierarchy

1. Availability + positioning
2. Outcome-led hero
3. Engineering system visualization
4. Capability pillars
5. FDE delivery model
6. Proof / ThreatFade and engineering evidence
7. Technical assessment CTA

## UX requirements

- Primary CTA remains visible on desktop and clear on mobile.
- Every major section has one dominant user action or information goal.
- Mobile layout collapses to one column without hiding critical content.
- Reduced-motion users receive the same information without animation dependence.
- Interactive elements expose clear hover/focus states.
- Color is never the sole carrier of meaning.

## V1 scope

V1 establishes the homepage design language. Core service, work, insight, contact, portal, and admin pages should reuse these primitives rather than introduce competing visual systems.
