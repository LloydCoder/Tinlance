# Security Policy

## Reporting a vulnerability

Do not open a public issue for a security vulnerability. Report suspected vulnerabilities privately to the Tinlance security contact published at tinlance.com.

Please include the affected component, impact, reproduction steps, and any relevant logs or screenshots. Do not include secrets or personal data.

## Security baseline

Tinlance follows a defense-in-depth approach covering dependency hygiene, secret management, secure headers, authentication and authorization boundaries, input validation, auditability, testing, and supply-chain controls.
